# Studio 启动与发布前验收

**状态：以下原生测试尚未执行。** 当前环境没有 Roblox Studio。自动化测试通过不能替代本表；建议先在独立测试体验完成 P0 项，再邀请 6–8 人实测。

## 1. 打开与启动

1. 保留旧体验备份；打开新版 `VaultBreakers.rbxl`，不要打开 `Place1.rbxl`。
2. 查看 Explorer：
   - `ReplicatedStorage/VaultBreakers`：Config、Network、Shared。
   - `ServerScriptService/VaultBreakers/Main`：服务器脚本，RunContext = Server。
   - `StarterPlayer/StarterPlayerScripts/VaultBreakers/ClientMain`：LocalScript。
3. 编辑态没有烘焙舞台；按 Play 后应出现 `Workspace/VaultWorld`、MAIN、QUICK、Lounge、Cameras，以及玩家 GUI `VaultBreakersUI`。
4. Output 应出现 Two independent studios ready / Client ready。未发布或禁用数据服务时出现临时体验提示是预期降级，不应卡住游戏。
5. 若二进制包不能打开：保留错误信息，尝试 `python3 scripts/build-place.py --xml .cache/VaultBreakers.rbxlx` 的 XML 版，或用官方 Rojo 从 `default.project.json` 构建。当前包只经过结构/源码逆向校验，未声称 Studio 导入成功。

### 使用 Rojo

在新建的空 Place 中同步当前项目。不要把新版脚本手工叠加在仍运行的旧 MatchManager/ClientMain 上。源码是权威来源；停止 Play 后再改文件、同步和重新 Play。

建议人数上限在体验发布设置中设为 **8**。最初禁用 StreamingEnabled 验收完整场景；当前所有源场景都直接存在于 Workspace，镜头/提示控制尚未针对动态流入流出做认证。本次增加了镜头/提示后到恢复，但这并不等于 Streaming 认证；日后启用时仍须重测流入流出、模型完整性和远端视角。

### 只读 Studio 检查入口

在 **Play 正在运行**、Output 出现 ready 之后，用 Command Bar 分别在 **Server** 与 **Client** 上执行：

```lua
require(game.ReplicatedStorage.VaultBreakers.Shared.StudioChecks).run()
```

- 服务端：检查双场、24 扇金库/交互锚点、可碰撞地板、有限位置/尺寸和零件预算。
- 客户端：额外读取可见文字的原生 `TextBounds`、固定按钮的安全区边界、交互高度；先切到菜单/报价/结算/帮助/设置，再分别运行。在中文、英文、竖屏和矮横屏各测一次。
- `ERROR` 优先修复；`WARN` 对照真实画面确认；`NO_TEXT_MEASUREMENTS` 表示尚无字体读数，等渲染后再运行，不能视为排版通过。
- 返回的 table 可展开查看每条问题的实例路径。检查不写 DataStore、不替玩家做选择、不修改场景；非 Studio 环境会直接拒绝。
- **这不是自动试玩。** 没有问题也不能证明网络、音频、物理、镜头遮挡、手柄焦点或保存正常。当前环境只测试了检查器自身的逻辑，尚无原生扫描报告。

## 2. P0 功能与权限

用本地 Server & Clients，先 3 个客户端，再 6–8 人真机服务器。每项记下设备、步骤、预期/实际及 Output 错误。

- [ ] A 进入 Main，B 进入 Quick，C 观看 Main；两套底牌、排除、时钟、投票、复位互不串扰。
- [ ] A 先 Claim，只有 A 的金库出现可用提示；C 靠近/尝试操作也不能更改 A 的对局。
- [ ] 打开其他金库后金额从可能结果中删除；Credits 此时不增长。底牌不可作为排除目标。
- [ ] 4 / 3 / 2 / 1 次排除后分别剩 8 / 5 / 3 / 2；四次 PUSH 后能进入最终二选一。
- [ ] 18 秒到时自动 PUSH，最终选择超时 KEEP；最后五秒无大面积频闪。用网络延迟模拟，在截止前点击但截止后才到达的 EXTRACT/SWAP 不应胜过服务器时钟；实体操作也遵守截止时间。
- [ ] EXTRACT 后按报价、KEEP/SWAP 后按所选金库支付；倍率是开局值；重复点击不能重复支付。
- [ ] C 的 EXTRACT/PUSH 意见只改变意见统计，不替 A 决策。修改意见不增加总人数。
- [ ] 观众回大厅/切换舞台/成为 Quick 选手后旧票立即消失；最终投票变成 KEEP/SWAP，不能沿用上轮标签。
- [ ] Main 第 3 轮起，A 可用一次红色杆：暂停原报价时钟、10 秒征求意见、恢复同一报价并至少留 6 秒；0 票与平票不伪造多数意见。
- [ ] Quick 没有求助和观众投票，不出现可用的假按钮。
- [ ] 报价/开门/揭晓期间晚加入的 C 不会从实例标签或快照读到未公开的金库金额。
- [ ] A 死亡/移除角色、重置、断线、AFK 或确认退局时释放场地；人为延迟新角色生成也不能占着旧舞台；未结算局不发奖，不扣掉此前已取得的余额。
- [ ] 队列多人时，重开不会插到既有队列前；偏好 Quick 的人不会被送入 Main。
- [ ] RESULT 到时舞台复位且下一人可上场；A 的复盘仍可阅读，关闭后可从纪录面板回看最近一局；重复同步不能重新强制弹出已关闭复盘。
- [ ] 打开网络延迟模拟，切换观看/进入另一场：新快照迟到时显示同步等待，不显示旧局按钮；两场同时变化时另一场消息不会解锁本场待确认的选择。
- [ ] 连续开局至少 10 次，门、锁栓、手轮、求助杆、标签和粒子完全复原；无旧 Tween 在新局突然播放。

## 3. P0 输入、镜头与排版

- [ ] 初次加入只有小型 HUD，菜单默认收起。无需关闭任何大页面就能走动、坐下、走到实体终端。
- [ ] M 与右上角按钮可反复呼出/收起；开启菜单没有切镜、传送、禁用移动或新增舞台命令。
- [ ] 帮助、选场、纪录、设置中的 × 直接回游戏；← 才是返回菜单。首次人称模式可操作鼠标，关闭后恢复相机操作。
- [ ] 开始/观战立即收起；返回大厅、重复同步、普通目录更新不强制展开。候场时收起菜单仍显示队列位置和取消入口。
- [ ] 手柄方向键上打开菜单，首个可用主按钮获得焦点；B 一次收起并释放 GUI 焦点。切换输入设备、滚动、子页返回和设置切换均可操作；不干扰 Roblox 核心菜单。
- [ ] 对局中打开菜单能看到「仍在进行」和剩余时间，按 1/2、X/Y 或实体 E/R2 不误操作；菜单不会延长时限，关闭后恢复正确控件。
- [ ] 核对金/青/蓝卡片、粗体标题和 3D 缩略图的原生效果；无正在进行的主场时观战按钮明确变暗。多次开关不重复创建缩略图模型。

- [ ] 桌面：1568×882 / 1360×800 / 1024×768；手机竖屏：390×844 / 360×640；横屏：844×414 / 844×390 / 568×320 / 568×260。以 **GUI 可用区域** 为准，另测实际刘海和 Roblox 顶栏扣除后的尺寸。
- [ ] 触摸时左下摇杆不被可点击按钮盖住，右下跳跃键仍可用；接近提示可触发，没有误投票/误退出。
- [ ] 字体在中文、英文和长 DisplayName 下不截断；金额表、报价、底牌、Heat、反馈和弹窗互不遮挡。离线边界测试未证明字形能装下。
- [ ] 手柄 R2 的实体提示可用，不会误触 X/EXTRACT；X/Y 二选一正确，导航焦点、滚动、关闭弹窗均可操作。
- [ ] 聊天输入时按 1/2 不触发决策；菜单/帮助/设置/退局页面打开时快捷键和实体 E/R2/触摸提示均不操作背后舞台；关闭后恢复正确权限，不能残留禁用。
- [ ] 观众镜头能完整看见舞台；选手正常阶段为角色镜头。揭晓镜头切向真正选中的门，结束/回大厅/重生后恢复视角和原 FOV。另测相机目标晚到、CurrentCamera 被重建，无需等待下一阶段也应恢复。
- [ ] 开启减少动态效果后没有揭晓切镜、画面变暗和压力边框脉动；中途切换设置也正常。
- [ ] 菜单小屏能滚动且关闭入口不随内容滚走；复盘长内容能滚动，重开/返回固定可点。舞台已释放后的复盘文字不再显示错误倒计时。
- [ ] 关闭声音后正在播放的循环也停止，再打开可恢复后续音效。

## 4. P0 存档与版本切换

**不要先在生产体验打开 Studio 数据访问做迁移试验。** 用独立测试体验、测试账户与可恢复的数据备份。

1. 发布测试体验；按 Roblox 当前设置启用 Studio API Services（仅测试体验）。无需启用 HTTP Requests，也无需在源码/聊天中填写账号密钥。
2. 完成一局，退出，重新加入，验证 Credits、声望、局数、Heat 与历史最佳。
3. 用旧格式样本验证 `cash / careerMatches / careerEarnings` 迁移；原始 inventory / hasPass / 未知根字段不应被清除。
4. 禁用/模拟数据服务故障：可临时游玩，提示本次不保存；加载失败不覆盖已有记录。
5. 模拟保存失败后恢复：显示 Save delayed，保留余额并在后续保存成功时清除提示。
6. 模拟跨服务器会话冲突与旧锁过期：活跃异服锁阻止写入，丢失锁的旧会话停止保存；验证真实 UpdateAsync 冲突重试行为。
7. 在加载未完成时离开并快速重连；在退出保存尚未完成时重连；验证新 Player 档案仍在，旧锁不被共用，余额来自真正已保存结果。必要时应明确提示临时模式，不能静默覆盖。
8. 在自动保存、离开保存、关闭服务器期间测试断线与服务预算不足。最后一次保存是尽力而为，不能保证 Roblox 后端故障时永不丢进度。

**迁移风险：旧服务器使用 SetAsync，不认识新锁。** 切换新版本时应停掉旧版本服务器，避免新旧代码同时写同一个 `User_<id>`。本次修改不会替你发布、关闭服务器或修改线上存档。

## 5. P1 模型、演出与性能

- [ ] 逐一走到 24 个金库：无穿墙、卡脚、地板空洞、门扫到角色或摄像机穿帮。
- [ ] 12 个座位都能坐/离开；坐着点击开局时先起身、再正确传送，座位不会被拖走。
- [ ] 检查金库内外的面、铰链方向、锁栓回缩、控制台正面左右、标签朝向、玻璃与栏杆尺度。
- [ ] 最低、中等、最高画质下都能读清铭牌和金额；Bloom 不洗白文字，金库背面不黑成一片。
- [ ] 验证 19 盏灯的实际影响范围/阴影代价；必要时先减少动态阴影和装饰光，而不是删掉关键提示。
- [ ] 6–8 人同时活动，观察客户端帧时间、服务器帧时间、内存和网络流量；记录 10 局后是否持续增长。目标中低端移动设备可稳定游玩，尚无实测 FPS 承诺。
- [ ] 记录真人的首局时长、到第一次选择的时间、排队时长、重复游玩与误解点。2–4 分钟和降低观战等待是目标，不能用纯状态机回归代替用户体验数据。
