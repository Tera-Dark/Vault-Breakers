# 设计与实现说明

## 不变的核心

Vault Breakers 不是「点击金库拿奖励」。选手守着未知底牌，主动排除其他可能性，再决定是否接受确定报价。观众提供社会压力，但没有控制权，也没有隐藏概率信息。玩家的损失感、后悔和庆幸来自公开信息下的取舍，不是付费下注。

本版明确保留：12 金库、Claim、实体移动/开门、Curator 报价、18 秒决策、EXTRACT/PUSH、Audience Lifeline、最终 KEEP/SWAP、Heat、Reputation、主舞台与并行快速场。目标局长 2–4 分钟；这仍是待真人测试的目标，不是已测得的中位数。

## 视觉语言

| 角色 | 色值 | 使用方式 |
|---|---|---|
| Ink | `#0C121B` | 深蓝黑背景、字卡底板 |
| Panel | `#141D27` | 大面板与金库深层结构 |
| Ivory | `#EEE7D4` | 主文字、控制台、铭牌 |
| Amber | `#DCAF63` | 确定性、报价、主按钮、身份标记 |
| Teal | `#67C8BD` | 继续、快速场、正向反馈 |
| Red | `#DE7971` | 最后五秒、求助杆、重要金额被排除 |
| Muted | `#9EB2BE` | 次级信息，避免低对比纯灰 |

用「克制的工业演播室」代替霓虹赌场：深色吸音墙、暖白铭牌、枪灰机械、琥珀色重点，保留日常可读性。用字、状态、位置、划线共同表达状态，不单靠红绿颜色。

### 模型

`VaultModel` 是中空结构，不是一个封死的大箱体：舱壁、深层背板、底座、双层圆形门、铰链、6 组锁栓/套筒、手轮/辐条、铭牌、铆钉、内侧灯带。锁栓先回缩，手轮旋转，整扇门围绕铰链 Pivot 转动。重置会取消 Tween、清粒子、还原组件，并用代次标记阻止旧延迟动画污染下一局。

`StageBuilder` 构造两套互不复用状态的演播室：

- 环形选手区、12 个独立金库、Curator 屏、观众意见屏。
- 实体双按钮控制台与可操作的红色求助杆；正面看左侧 EXTRACT、右侧 PUSH，与 HUD 对应。
- 灯架、摄影机、吸音板、后景标识与栏杆。
- 升高的休息室、12 个真实 Seat、玻璃前沿、桌几、饮品台和规则海报。

全部使用 Roblox 原生几何与 SurfaceGui，不依赖上传的网格、贴图或营销图。缺点也明确：这里不是 PBR 高模资产包，真实材质、阴影、玻璃和角色尺度仍待 Studio 现场调校。

### UI

- 世界优先：默认收起菜单，只显示小型积分/Heat HUD 和入口。没有常驻大厅 scrim，也不为菜单强制切镜头或禁用 PlayerModule。
- 菜单：Fredoka One 粗体品牌、厚描边与金/青/蓝入口卡片，选择舞台 / 开始游戏 / 观战；原生 ViewportFrame 内使用原创的金库、方块角色和摄像机缩略模型。三张图总计 205 个本地零件，首次打开才构建并长期复用，不克隆运行中场地/其他玩家，不访问隐藏值。
- M、右上角按钮、手柄方向键上/B 提供明确的开关。关闭与返回菜单分开；菜单状态不从 Directory/Snapshot 推导，普通同步和回大厅不强制展开。开始/观战立即收起，排队提示独立于菜单。
- 子页面：选场、玩法、个人/本服纪录、设置；每页可一键回游戏。在手机竖屏需要时只滚动菜单内容，关闭控件固定在安全区；常见矮横屏保留三张卡和 44px 次级按钮。
- 原对局 HUD 不被菜单行为替代：菜单打开时不暂停服务器时钟，显示未暂停/倒计时提示，关闭后恢复局内操作。没有顺便添加商店、背包、兑换码或付费进度。
- 局内：先看身份/阶段，再看剩余奖池，最后聚焦报价/选择。排除的金额划线且降对比；底牌和已锁定 Heat 单独标识。
- 观众和选手使用不同文案/权限；投票不会变成选手操作。
- 矮横屏触摸布局把奖池做成顶部两行，选择区移到右下，给左下移动输入留空间。主要按钮高至少 44 像素。
- 结算金额、底牌、下一局 Heat 与当时的决策理由分层显示；内容滚动，重开/返回固定。舞台释放后复盘仍可读，不强制抢走阅读时间。
- 减少动态效果关闭揭晓切镜、变暗和临界边框脉动；声效可关闭。不做全屏频闪。

## 权威流程

```text
IDLE → CLAIM → BREACH ⇄ OPENING
                      ↓ 配额完成
                    OFFER ⇄ LIFELINE（主舞台一次）
                      ↓ PUSH
                 TRANSITION → 下一轮 BREACH
                      ↓ 第四次 PUSH
                 FINAL_CHOICE
                      ↓ KEEP / SWAP
EXTRACT ───────────→ REVEAL → RESULT → IDLE
```

每局递增 `runId`，每阶段递增 `phaseId`；快照每次更改递增 `revision`，Directory 另带序号与各场次/阶段下界；客户端的阶段动作必须带上二者。服务端同时校验身份、观看范围、选项、当前状态；实体交互另校验距离。开门在启动动画前就进入 OPENING 锁定输入；结算只产生一次事件。

时间来自服务器绝对时钟，客户端只显示剩余时间，不决定超时。规则方法与网络/实体适配层都先处理截止时刻，自动动作走明确的内部路径，防止超时递归和最后一帧抢旧报价。状态机没有 Instance、task 或远程事件依赖，测试直接注入随机数与时间。

### 观看与客户端恢复

`ClientState` 是纯状态归并模块：跨 Snapshot/Directory 到达顺序均可收敛；旧场次、旧阶段、同阶段较旧修订与旧 Directory 不能回退画面。新分配尚无对应快照时隐藏舞台操作、显示同步卡，并有限频率请求 SYNC。

每个待确认操作绑定 arena/run/phase；其他舞台快照不能取消它。2 秒未确认只重新同步，不盲目重放选择。最近复盘和当前舞台分离，按场次记录已显示/已关闭状态，重复 RESULT/SYNC 不夺回界面。

切换观看范围会先处理原场时钟并撤回旧票。死亡/角色移除释放场地且断开旧角色监听；关闭服务器后不再接受新操作。

相机仅在找到目标后缓存成功状态，检测 CurrentCamera 替换并分别还原相机/FOV；客户端以 0.2 秒间隔尝试恢复，不逐帧重建 UI。提示缓存仅保存约 32 个 ProximityPrompt，监听后到/移除对象，并以 1 秒兜底刷新后到属性；菜单、子页面、复盘与同步等待统一关闭实体输入。退出菜单时清除本 UI 的手柄焦点并撤销 Modal 鼠标释放状态；聊天输入和已处理的键盘事件不抢键。服务端距离/身份/时钟验证仍是最终防线。

### 公开信息边界

客户端可以知道**剩余金额集合**，但不能知道每个未开金库对应哪个金额。开门动画中、揭晓动画中、晚加入快照中仍遵守这个边界。只有阶段结束时才公开相应值，RESULT 才公开完整映射。镜头只拿到 `revealId`，不提前拿到底牌金额。

5 个事件：`Action / Snapshot / Directory / Profile / Notice`。没有让客户端指定奖金额度、任意角色、任意结算或任意领取物品的接口。输入限流是突发 10、每秒恢复 5；服务器镜头/UI 本地隐藏并非权限防线，权限仍在服务器。

### 决策质量，而非运气评价

`DecisionQuality` 仅接收该时点的报价、EV、剩余奖池，使用金额跨度与平方根效用的确定性等价作解释。它是可读的风险偏好启发式，**不是唯一正确策略，也不是概率预测器**。

- 合理的确定性兑现或仍有明显空间的 PUSH：`+1`。
- 可以理解的保守/冒险选择：`0`。
- 高报价且几乎没有上行空间时仍 PUSH：可能 `-1`。
- 自动决策中性；最终两个未知金库的 KEEP/SWAP 不按结果倒推对错。

质量分 `0 / 3 / 7 / 12` 对应 Heat `1.0 / 1.2 / 1.5 / 2.0`。新 Heat 只影响后续开局，当前结算使用开局锁定值。完成一局 `+2 Reputation`，每次正向质量评价额外 `+2`。观众意见无押金、无兑付、无预测收益。

## 数据与榜单

- 档案新增 v2 嵌套 profile。旧 `cash / careerMatches / careerEarnings` 分别迁移为 Credits / 局数 / 历史最佳字段；旧格式无法准确拆分 EXTRACT、最终选择与倍率，保留历史值而不伪造详细历史。
- 旧根层库存、通行证与未知字段仍保留；新 UI 不暴露这些不属于本版规则的功能。
- 决策质量分没有可靠旧记录可继承，因此 Heat 从新质量分计算，不凭旧奖金追认「好决策」。
- 加载失败/锁冲突：临时模式、禁止写回。暂时保存失败：`SAVE_DELAYED`，提示并保留内存数据等待重试。锁丢失：停止写入。
- 每次加载绑定具体 Player 和独立锁 ID；异步保存捕获条目，清理时比较当前条目身份。快速重连最多等旧会话退役 8 秒；退出先最多等在途保存 20 秒，再重试释放。超时/后端失败仍可能降为临时模式或丢失尚未保存的进度，不承诺永不丢档。
- 本服纪录只由**本服务器实际完成的对局**登记，不拿载入的历史档案冒充现场成绩；按本次服务器内最佳**基础奖励**排序，保存至多 8 条，避免长期开服无限增长。Reputation 列是玩家当时的生涯声望，不是全服排行榜。

## 测试工具的边界

`check.mjs` 使用固定版本的 Luau WASM 编译并执行真实规则模块。`contract-check.mjs` 的 integration / resilience / menu 三套测试执行真实 Main 与 ClientMain，但依赖自行实现的 Roblox doubles，反射 fixture 来自 Roblox Client Tracker API blob `ffaefea669c2a882496dc9d5183b3db146e251db`。

现有 21 组规则、7 组客户端纯状态、16 组入口/布局、17 组边界、9 组菜单交互测试；后三套使用复制的传输/存档 payload、手动控制消息交付、可延迟的存档请求与可暂停 Heartbeat 的时钟。它们仍不模拟 Roblox 的真正跨客户端传输或后端事务。

`StudioChecks` 只在 Studio 接受手动调用，读取对象、原生 TextBounds 和按钮边界，返回报告并输出问题；不访问 DataStore，不自动操作玩家。零个问题也不是整体验收通过，必须独立完成输入、碰撞、多人和真实存档检查。

WASM 自带约 17 MiB 固定堆不够容纳两套模拟场景/GUI，测试入口通过 Emscripten 的实例化 hook 把内存声明扩大为 64 MiB，不改 Luau 字节码。这是测试运行器配置，**不是 Roblox 游戏内存占用数据**。

离线图片由生产几何/GUI 坐标生成，使用简化深度测试与替代字体；仅对 ViewportFrame 的原生缩略模型、描边和渐变做近似绘制，不提供 Roblox 光照、SurfaceGui、真实字体尺寸、角色/PlayerModule 相机或原生 ViewportFrame 渲染。所有图片应标注「离线检查」，不得作为游戏实机截图发布。
